fetch API：请求、解析与错误处理

本页不联网：下面的"服务器"是一个用 Promise + 原生 Response 构造函数 实现的本地模拟服务器，返回值的类型和行为与真实的 fetch 完全一致。 只有最后一组按钮会真正调用一次 fetch（请求 data: URL，不产生网络流量）。

1. 基本 GET mock

演示 response.ok / status / headers / json() 的读取方式。

2. POST 提交 JSON mock

演示 method / headers / body 三件套，以及 201 状态码。

3. HTTP 错误不等于网络错误 最重要

404 / 500 时 fetch 的 Promise 依然是"成功"的，必须自己检查 response.ok。

4. 网络错误与超时取消 mock

连接失败时才 reject；超时要用 AbortController 手工实现。

5. 响应体只能读一次 陷阱

json() 之后再 text() 会抛 "Body has already been read"。

6. 并发与手写 Response

Promise.all 并发发请求；Response 构造函数可以本地造假数据。

7. 真实的 fetch 调用 真 API

请求一个 data: URL——这是真正的 fetch，但不会产生任何网络流量。 在 file:// 协议下如果被安全策略拦截，会被 try/catch 捕获并如实提示。
