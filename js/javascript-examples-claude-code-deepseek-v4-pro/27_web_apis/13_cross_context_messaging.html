跨上下文通信：postMessage / BroadcastChannel / storage

浏览器的标签页、iframe、弹窗之间默认是完全隔离的，只能通过"消息"通信。 本页把三条通道都做成可点的演示，右侧日志实时打印每一次发送、接收、拒绝和异常。 本页是双击打开的 file:// 页面，所有受限操作都已用 try/catch 兜住并给出提示。

1. postMessage —— 点对点通信

下面绿框里是一个真正的独立文档（<iframe srcdoc>）， 它有自己的 window 和 JS 环境，和本页互相看不到对方的变量，只能靠 postMessage 说话。

结构化克隆实验台：选一种数据发给 iframe，看看哪些能过、哪些会抛错。

当前 origin 校验：开启 （关掉之后，任何来源的消息都会被当成命令处理——这就是漏洞的样子）

4. 三条通道速查

postMessage 点对点。必须显式指定目标窗口，targetOrigin 限定可达范围。 接收方必须自己校验 event.origin。 BroadcastChannel 同源广播。同频道名的实例都收得到（发送者除外）。 能传结构化克隆的任意数据，页面关闭即消失。 storage 事件 同源广播，但由"写 localStorage"隐式触发。 消息只可能是字符串；会持久化到磁盘； 发送者自己收不到；值没变不触发。

一句话记忆：postMessage 是寄快递（写清地址、验明发件人）； BroadcastChannel 是大喇叭（同源都能听见，喊的人自己听不见）； storage 事件是储物柜响了一声（谁动了柜子，同源的其他人都会收到提醒）。
