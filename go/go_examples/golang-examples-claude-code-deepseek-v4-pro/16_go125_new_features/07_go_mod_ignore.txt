go.mod ignore 指令 — Go 1.25
===========================


1. 概述
-------

Go 1.25 新增 go.mod 中的 ``ignore`` 指令，用于排除特定目录，
使其不被 ``go`` 命令在包匹配时扫描（如 ``./...``, ``all`` 等）。

这对于包含非 Go 代码的目录（如前端构建输出、node_modules、
生成代码目录）特别有用。


2. 语法
-------

单目录：
    ignore ./node_modules

多目录块形式：
    ignore (
        ./node_modules
        ./bazel-out
        static
        content/html
    )


3. 路径规则
-----------

- ``./`` 前缀：路径相对于模块根目录
  （如 ``ignore ./foo/bar`` 只匹配模块根下的 foo/bar）

- 无前缀：匹配模块树中任意深度同名的目录
  （如 ``ignore node_modules`` 匹配所有 node_modules 目录）


4. 行为
-------

+----------------------+----------------------------------------------------+
| 方面                  | 说明                                                |
+----------------------+----------------------------------------------------+
| 包匹配               | ./...、all 等模式跳过忽略的目录                      |
| 模块 zip             | 忽略的目录仍包含在 module zip 中（保持一致性）       |
| gopls / go list      | 跳过扫描这些目录                                    |
| 可见性               | 等同于 _ 或 . 前缀目录                              |
| Go 版本要求          | 仅当 go.mod 的 go 行 >= 1.25 时生效                  |
+----------------------+----------------------------------------------------+


5. 示例
-------

创建一个简单的 go.mod：

    module myapp

    go 1.25

    ignore (
        ./web/node_modules      # 前端依赖
        ./build/generated        # 生成代码
        ./docs/_site             # 文档构建输出
    )


6. 适用场景
-----------

- 前端构建输出（Angular/React/Vue 的 node_modules）
- 代码生成器输出目录
- 大型文档站点
- Bazel / Make 等构建工具的输出目录
- 任何不包含 Go 源代码且不需要被 go 命令扫描的目录


7. 与 vendor 的关系
-------------------

ignore 和 vendor 是独立功能：
- vendor 复制依赖代码到本地
- ignore 排除目录不参与包匹配
- 两者可以同时使用


8. 注意
-------

- ignore 目录仍然存在于文件系统中，只是不参与包匹配
- go list ./... 不会列出 ignore 目录中的包
- go build ./... 不会编译 ignore 目录中的代码
- 如果目录包含 Go 源文件但被 ignore，go 命令将"看不到"它们
